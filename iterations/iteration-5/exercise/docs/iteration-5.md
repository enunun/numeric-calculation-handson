# Iteration 5の手順：指数関数とULP精度

このIterationでは，`Float64`の指数関数exp(x)を作る．
引数を還元して多項式で近似し，各段の誤差を足し合わせる誤差予算で，誤差の上界をULPで示す．
上界は実測ではなく理論から導き，それをテストの許容誤差にする．
作業はすべて`iterations/iteration-5/exercise/`で行う．

## 5-2 文法と概念

[Juliaのノート](../../../../docs/julia/iteration-5.md)と[理論のノート](../../../../docs/theory/iteration-5.md)を読み，REPLで次の課題を解く．

1. `exp(1.0)`と`exp(big(1.0))`を比べ，`exp(1.0)`の誤差がULPでいくつかを手で計算する．eは区間(2以上4未満)にあるので，ULPは2⁻⁵¹である．
2. `bitstring(6.93147180369123816490e-01)`の最後の21文字が0であることを確かめる．
3. x = 693.0，k = 1000について，`x - k * log(2.0)`と`big(x) - k * log(big(2))`を比べる．
4. |r| ≤ ln 2/2で，12次と13次のテイラー多項式の打ち切り誤差の上界(|r|のN + 1乗を(N + 1)の階乗で割り，e^|r|を掛けた値)を，r = ln 2/2で計算する．
5. `evalpoly(0.3, Tuple(1 / factorial(j) for j in 0:13))`と`exp(0.3)`を比べる．
6. `ldexp(1.5, -1074)`と`ldexp(1.5, -1073)`を計算し，非正規化数の範囲では`ldexp`も丸めることを確かめる．
7. `[nextfloat(1.0, k) for k in 1:5]`で，1.0の次の5つの数を列挙する．

## 5-3 テストリスト

次の要件と使用例を読み，`TESTLIST.md`に確かめる振る舞いを書き出す．

### 要件

- `Float64`の指数関数exp(x)を計算する．誤差の上界を誤差予算で示し，結果が正規化数なら1.3 ULP以下，非正規化数なら1.8 ULP以下とする．
- `NaN`は`NaN`，`Inf`は`Inf`，`-Inf`は`0.0`を返す．
- 結果が`Float64`の最大値を超える引数では`Inf`を返し，非常に小さい結果は非正規化数または`0.0`になる(x > 710では`Inf`，x < −746では0.0)．
- 計算結果のULP誤差を，高精度の参照解と比べて求められる．

### 使用例

```julia
julia> exponential(1.0), exponential(-Inf), exponential(710.0)
(2.7182818284590455, 0.0, Inf)

julia> ulp_error(exponential(0.5), exp(big(0.5)))
0.21309090040865203
```

### 作るもの

- `ElementaryFunctions`(新規)
  - `reduce_argument(x::Float64)`：x = k·ln 2 + r(|r| ≤ ln 2/2)となる`(k, r)`を返す(Cody–Waiteの方法)．
  - `exponential(x::Float64)`
- `ErrorBounds`：`ulp_error(computed::AbstractFloat, exact::BigFloat)`を加える．ULPは，正しい値の絶対値が属する区間(2ᵉ以上2ᵉ⁺¹未満)の数の間隔で測る．

### 考えること

- 「誤差1 ULP未満」と主張するには，何が必要か．実測で誤差が小さいことは保証になるか．
- `ulp_error`のULPを，計算値と正しい値のどちらの位置で測るか．正しい値が2の冪のすぐ下にあるとき，結果はどう変わるか．
- 誤差が大きくなりやすい入力はどこか．還元の切り替わり，結果の大きさが変わる点(オーバーフロー，非正規化数の始まり)を考える．
- 参照解を使わずに確かめられる性質はあるか．その性質は，実装の誤差の上界から導けるか(例えば単調性は導けるか)．
- 信頼できる別の実装(`Base.exp`)と比べるとき，許容誤差はどう決めるか．相手の誤差について，何を仮定するか．
- 時間のかかる検査をどう分け，どう実行するか．

## 5-5 テストファーストの実装

### ErrorBounds

`ulp_error`は，`exponent`で正しい値の区間の指数eを求め，間隔2ᵉ⁻⁵²で割る．
非正規化数の範囲では，eを`exponent(floatmin(Float64))`で下から抑える．
`prevfloat(1.0)`と`1.0`のように，区間の境界をまたぐ組をテストに入れる．

### ElementaryFunctions

- Cody–Waiteの定数は，LN2_HI = 6.93147180369123816490e-01，LN2_LO = 1.90821492927058770002e-10を使う．
- kは`round(Int, x / log(2.0))`で求める．
- exp(r)は1 + s，s = r + r²Q(r)で求める．Qの係数(j + 2の階乗の逆数)は，`BigInt`の`factorial`で計算してから`Float64`に丸める．
- 2ᵏを掛けるのは`ldexp`で行う．
- 特殊値とオーバーフロー，アンダーフローの場合分けを先に書く．

### テスト

- 参照解は`exp(BigFloat(x))`で求め，`test/helpers.jl`に置く．誤差予算から決めた上界も定数としてそこに置く．
- 標本検査では，全範囲から一様に選ぶ点と，0の近くを細かく選ぶ点を使う．
- 局所的な全数検査は`test/exhaustive/`に置き，`test/runtests.jl`に新しいグループ`exhaustive`を加える．`Pkg.test(test_args = ["exhaustive"])`で，そのグループだけを実行できることを確かめる．

### よくある間違い

- 還元に`x - k * log(2.0)`を使う．|x|が大きいと誤差が数百ULPになる．
- 多項式の次数が足りない．打ち切り誤差が丸め誤差を上回る．
- 許容誤差を実測の最大値から決める．データを変えると不合格になりうるうえ，根拠を説明できない．
- 単調性をテストする．上界が1 ULPを超えるので保証されない．

## 5-7 発展課題

`Float32`の指数関数`exponential32(x::Float32)`を作る．
`Float64`の`exponential`で計算してから`Float32`に丸める方法が使える．
入力の区間(1以上2未満)のすべての`Float32`(2²³個)について，`Float32`のULP誤差を検査する．
参照解は`exp(Float64(x))`で十分か，理由とともに考える．
