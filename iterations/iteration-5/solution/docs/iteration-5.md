   ```julia

   ```

3. 素朴な還元では，rの誤差が約6.8 × 10⁻¹⁴になる(理論のノートの3節)．

4. 12次では約2.4 × 10⁻¹⁶(数ULP)，13次では約5.9 × 10⁻¹⁸(約0.05 ULP)である．

   ```julia
   julia> ρ = log(big(2)) / 2; Float64.((ρ^13 / factorial(big(13)) * exp(ρ), ρ^14 / factorial(big(14)) * exp(ρ)))
   (2.3636095246913186e-16, 5.8511759928015e-18)
   ```

5. この点では一致する．

   ```julia
   julia> evalpoly(0.3, Tuple(1 / factorial(j) for j in 0:13)), exp(0.3)
   (1.3498588075760032, 1.3498588075760032)
   ```

6. 1.5 × 2⁻¹⁰⁷⁴は，最小の非正規化数2⁻¹⁰⁷⁴とその2倍のちょうど中間なので，偶数側の2 × 2⁻¹⁰⁷⁴に丸められる．1.5 × 2⁻¹⁰⁷³ = 3 × 2⁻¹⁰⁷⁴は表せる．

   ```julia

   ```

7. 1.0000000000000002，1.0000000000000004，1.0000000000000007，…と，2⁻⁵²ずつ増える．

## 5-3 テストリスト

模範解答は[TESTLIST.md](../TESTLIST.md)にある．
項目を選ぶときに考えたことを説明する．

### 上界は誤差予算から決める

テストの許容誤差は，誤差予算で導いた上界(正規化数1.3 ULP，非正規化数1.8 ULP)である．
実測の最大値(0.93 ULP)から許容誤差を決めると，根拠がなく，データを増やすと不合格になりうる．

### ULPの測り方

`ulp_error`は，正しい値の位置でULPを測る．
計算値の位置で測ると，正しい値が2の冪のすぐ下にあり，計算値が2の冪に丸められたとき，ULPが2倍になって誤差を小さく見積もる．
区間の境界をまたぐ組(`prevfloat(1.0)`と1.0など)をテストに入れて，この定義を確かめる．

### 4種類の検査

| 検査 | 項目 |
| --- | --- |
| 標本検査 | 全範囲から一様に500点と，0の近くから200点(10個のシード) |
| 境界値検査 | オーバーフローの直前，正規化数と非正規化数の境，0になる直前，±ln 2/2の前後，0の近く |
| 局所的な全数検査 | 1.0，±ln 2/2，log(floatmin)の前後1万個ずつ |
| 差分テスト | `Base.exp`との比較(10個のシードで10万点) |

### 性質

exp(x)·exp(−x) = 1は，上界から許容誤差2δ + δ²(δ = 1.3 × 2u)を導ける．
単調性は，上界が1 ULPを超えるので保証されず，テストしない．

## 5-5 テストファーストの実装

### ulp_error

`ulp_error(1.0, big(1.0)) == 0.0`は仮実装で通り，`nextfloat(1.0)`の項目で一般化を迫られる．
`prevfloat(1.0)`の項目で，ULPを計算値ではなく正しい値の位置で測ることが確かめられる．

```julia
function ulp_error(computed::T, exact::BigFloat) where {T<:AbstractFloat}
    smallest_exponent = exponent(floatmin(T))
    e = iszero(exact) ? smallest_exponent : max(exponent(exact), smallest_exponent)
    spacing = BigFloat(2)^(e - (precision(T) - 1))
    return Float64(abs(BigFloat(computed) - exact) / spacing)
end
```

最初は`ulp_error(-2.0, big(-2.0) - big(2.0)^-51)`を0.5と予想してテストを書いたが，実装は1.0を返して不合格になった．

```text
ulp_error: Test Failed at …/test/unit/error_bounds_tests.jl:55
  Expression: ulp_error(-2.0, big(-2.0) - big(2.0) ^ -51) == 0.5
   Evaluated: 1.0 == 0.5
```

正しい値の絶対値2 + 2⁻⁵¹は区間(2以上4未満)にあり，間隔は2⁻⁵¹なので，1.0が正しい．期待値の誤りだったので，期待値を直してコメントで理由を書いた．

### reduce_argumentとexponential

`reduce_argument(0.0) == (0, 0.0)`の項目から始め，誤差の項目でCody–Waiteの分割を入れる．

```julia
function reduce_argument(x::Float64)
    k = round(Int, x / log(2.0))
    r = (x - k * LN2_HI) - k * LN2_LO
    return (k, r)
end
```

`exponential`は，特殊値と境界の項目を先に通してから，標本検査の項目で多項式を入れる．

```julia
function exponential(x::Float64)
    isnan(x) && return x
    x > 710.0 && return Inf
    x < -746.0 && return 0.0
    k, r = reduce_argument(x)
    s = r + r * r * evalpoly(r, Q_COEFFICIENTS)
    return ldexp(1.0 + s, k)
end
```

`Inf`は`x > 710.0`で，`-Inf`は`x < -746.0`で処理される．

### 局所的な全数検査

`test/exhaustive/exponential_exhaustive_tests.jl`では，中心の前後の連続する数を`nextfloat`と`prevfloat`で作り，ULP誤差と上界の比の最大値が1以下であることを確かめる．
4つの中心で合わせて約8万点を調べる．

### 間違った実装を見つけられるか

| 間違い | 不合格になったテスト |
| --- | --- |
| 多項式を12次にする | 標本検査(47点)，局所的な全数検査(2区間) |
| 還元を`x - k * log(2.0)`にする | 還元の誤差(5件)，標本検査(4783点)，差分テスト(95521点)，局所的な全数検査(1区間) |

12次の多項式の誤差は，打ち切り誤差の大きい|r| ≈ ln 2/2の近くだけで上界を超える．
乱数の標本では47点しか当たらないが，局所的な全数検査は±ln 2/2の前後を集中的に調べるので確実に見つける．

## 5-6 振り返り

1. 模範解答のリストには，ULPの測り方を区間の境界で確かめる項目と，保証されない性質(単調性)をテストしないという判断が含まれている．
2. 標本検査と局所的な全数検査の両方が失敗する．局所的な全数検査は，誤差が出やすい点を狙って調べるので，乱数の標本より確実に見つける．
3. 還元の誤差，標本検査，差分テスト，局所的な全数検査が失敗する．|x|が大きい点で誤差が大きいので，全範囲からの標本と差分テストで多く見つかる．
4. 評価(0.49)と還元(0.25)が大きい．rを2つの浮動小数点数の和で持ち，sの計算で低い位の項を補正すると，両方を減らせる．
5. `Base.exp`の誤差が仮定より大きいと，正しい実装でも差分テストが不合格になりうる．差分テストの結果を信頼するには，比べる相手の精度を別の方法で確かめておく必要がある．模範解答では，標本検査のついでに測った`Base.exp`の誤差(最大0.72 ULP)を誤差仕様書に書いた．
6. 模範解答では，設計文書と実装は一致している．`mise run design iterations/iteration-5/solution`で確かめられる．
7. コース全体の手法は次のとおりである．

   | 手法 | 使った問題 |
   | --- | --- |
   | 厳密な参照解(有理数) | 総和，判別式，分散，連立1次方程式，最小二乗法 |
   | 無誤差の主張の検査 | `two_sum`，`two_prod` |
   | 高精度の参照解(`BigFloat`) | 二次方程式の根，指数関数 |
   | 性質 | 解と係数の関係，分散の非負性，最適性条件，exp(x)·exp(−x) = 1 |
   | メタモルフィック関係 | 分散の平行移動と並べ替え |
   | 後退誤差 | 二次方程式の根，連立1次方程式，三角行列 |
   | 製造解 | 最小二乗法，多項式の当てはめ |
   | 差分テスト | 指数関数(`Base.exp`) |
   | 局所的な全数検査 | 指数関数 |

## 5-7 発展課題

`Float64`で計算して丸める解答例を示す．

```julia
exponential32(x::Float32) = Float32(exponential(Float64(x)))
```

`Float64`の結果の誤差(1.3 ULP₆₄以下)は，`Float32`のULPの2⁻²⁹倍程度なので，丸めた結果の誤差は0.5 ULP₃₂をわずかに超える程度に収まる．
参照解の`exp(Float64(x))`の誤差も同じ理由で無視できる．
1以上2未満の2²³ = 8388608個の`Float32`をすべて調べた．ULP誤差の最大値は0.4999999813735485で，この範囲では正しく丸められていた．
すべての点を調べるのに1秒もかからない．
`Float32`の入力は2³²個しかないので，この方法なら全範囲の全数検査も現実的である．
