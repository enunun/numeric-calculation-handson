# ADR 0001：補償付き総和にSum2を使う

## 状況

素朴な総和の相対誤差の上界はγₙ₋₁·κで，条件数κが大きいデータ(大きな値どうしの打ち消しを含むデータ)では正しい桁が残らない．
例えば`[1e16, 1.0, -1e16]`の素朴な総和は0.0になり，正しい値1.0と比べた相対誤差は1である．
作業精度(`Float64`)のまま，条件数の大きい総和を正確に求める方法が必要である．

## 決定

`compensated_sum`には，Ogita–Rump–OishiのSum2を使う．
各段の和を`two_sum`で丸めた和と丸め誤差に分解し，丸め誤差を別の変数に集めて最後に足す．

ほかの候補と比べた結果は次のとおりである．

- Kahanの補償付き総和：各段の補正が次の加数に吸収されて失われる場合があり，`[1e16, 1.0, -1e16]`では0.0を返す．
- 対ごとの総和(pairwise summation)：相対誤差の上界がおよそlog₂n·u·κに下がるが，κに比例する点は変わらない．
- 有理数や`BigFloat`による計算：正確だが遅く，入力と同じ型で返すライブラリの関数には向かない(テストの参照解には使う)．

## 結果

- 相対誤差の上界はu + γₙ₋₁²·κになる．κ ≪ 1/(n²u)なら，結果は2倍の精度で計算して丸めた場合と同程度に正確である．
- 1要素あたりの浮動小数点数の演算は，素朴な総和の1回から7回に増える．

## 検証

- `two_sum`の無誤差性(a + b = s + e)を，有理数に直して厳密に検査する．
- `compensated_sum`の相対誤差が誤差界u + γₙ₋₁²·κ以下であることを，条件数が1から10¹⁶程度までのデータで検査する．参照解は有理数で求めた厳密な総和である．
