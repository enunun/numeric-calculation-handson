# Iteration 5：指数関数と誤差予算

このノートでは，指数関数exp(x)を作り，その精度をULPで保証する方法を学ぶ．
計算の各段の誤差を見積もって足し合わせる「誤差予算」で上界を導き，標本，境界，全数，差分の4種類の検査で確かめる．

## 1. ULP誤差

初等関数の精度は，相対誤差よりもULP(unit in the last place)で表すことが多い．
このコースでは，正しい値yの絶対値が属する区間(2ᵉ以上2ᵉ⁺¹未満)の数の間隔2ᵉ⁻⁵²を1 ULPとし，計算値ŷの誤差を|ŷ − y|/2ᵉ⁻⁵²で測る．
非正規化数の範囲では，間隔は2⁻¹⁰⁷⁴で一定である．

```julia
julia> ulp_error(exponential(0.5), exp(big(0.5)))
0.21309090040865203
```

ULPで測ると，「最も近い浮動小数点数に丸めた」ことが「誤差0.5 ULP以下」に対応する．
相対誤差との関係は，1 ULP = 2ᵉ⁻⁵²が|y|のu倍から2u倍の間にあることから決まる．
相対誤差δは，およそδ/(2u)からδ/u ULPにあたる．

## 2. 正しい丸めと忠実な丸め

- 正しい丸め(correctly rounded)：結果は，正しい値を最も近い浮動小数点数へ丸めた値と一致する．誤差は0.5 ULP以下である．IEEE 754は四則演算と平方根に正しい丸めを要求する．
- 忠実な丸め(faithful rounding)：結果が，正しい値を挟む2つの浮動小数点数のどちらかである．誤差は1 ULP未満である．

初等関数を常に正しく丸めるのは難しい．
正しい値がちょうど2つの浮動小数点数の中間に非常に近いと，どちらに丸めるべきかを決めるのに，非常に高い精度で計算する必要がある．
これをテーブルメーカーのジレンマと呼ぶ．

```julia
julia> exp(1.0), exponential(1.0)
(2.718281828459045, 2.7182818284590455)

julia> ulp_error(exp(1.0), exp(big(1.0)))
0.32553074014505834

julia> ulp_error(exponential(1.0), exp(big(1.0)))
0.6744692598549417
```

`Base.exp(1.0)`は正しく丸めた値を返し，`exponential(1.0)`は隣の浮動小数点数を返す．
どちらも正しい値eを挟む2つの数なので，忠実な丸めにはなっている．

## 3. 引数還元

exp(x)のテイラー級数をそのまま計算すると，|x|が大きいとき多くの項が要り，x < 0では大きな項どうしの打ち消しで桁落ちする．
そこで，指数関数の性質exp(k·ln 2 + r) = 2ᵏ·exp(r)を使い，xを小さなrに還元する．

```text
k = round(x / ln 2),   r = x − k·ln 2,   |r| ≤ ln 2/2 ≈ 0.347
```

2ᵏを掛けるのは指数部を変えるだけなので，正規化数の結果では丸め誤差が生じない．Juliaでは`ldexp(y, k)`で計算する．

### Cody–Waiteの方法

r = x − k·ln 2の計算では，|x|が大きいとき，x ≈ k·ln 2の引き算で桁落ちが起きる．
ln 2は浮動小数点数で表せず，k·ln 2の積も丸められるので，その誤差が拡大される．

```julia
julia> k = 1000; x = 693.0;

julia> Float64(big(x - k * log(2.0)) - (big(x) - k * log(big(2))))
6.848756754316938e-14
```

rの誤差6.8 × 10⁻¹⁴は，結果exp(x) = 2ᵏ·exp(r)の相対誤差としてそのまま現れ，数百ULPになる．

Cody–Waiteの方法では，ln 2を2つの浮動小数点数の和LN2_HI + LN2_LOに分ける．
LN2_HIは仮数の下位ビットが0になるように選ぶ(このコースの値では下位21ビットが0)．
すると，|k| < 2²¹ならk·LN2_HIは丸めずに計算でき，x − k·LN2_HIもSterbenzの補題から厳密になる．

```text
r = (x − k·LN2_HI) − k·LN2_LO
```

残る誤差は，最後の引き算の丸め(u|r|程度)，k·LN2_LOの丸め(とても小さい)，ln 2 = LN2_HI + LN2_LOの分割誤差(約1.2 × 10⁻²⁶)のk倍である．

```julia
julia> r = (x - k * 6.93147180369123816490e-01) - k * 1.90821492927058770002e-10; Float64(big(r) - (big(x) - k * log(big(2))))
-1.319307620277554e-17
```

## 4. 多項式による近似

|r| ≤ ln 2/2でexp(r)をテイラー多項式で近似する．N次の多項式の打ち切り誤差(剰余)は次のとおりである．

```text
|exp(r) − Σᵢ₌₀ᴺ rⁱ/i!| ≤ |r|ᴺ⁺¹/(N + 1)! · e^|r|
```

N = 13では約5.9 × 10⁻¹⁸(約0.05 ULP)，N = 12では約2.4 × 10⁻¹⁶(数ULP)である．
打ち切り誤差は丸め誤差よりずっと小さくしたいので，13次を選ぶ．

計算は，exp(r) = 1 + s，s = r + r²Q(r)と分ける．Q(r)はrʲ/(j + 2)の階乗をj = 0から11まで足した多項式である．
sは小さい(|s| ≤ 0.42)ので，sの計算の丸め誤差は，最後の1 + sに比べて小さくなる．

## 5. ホーナー法の成分ごとの誤差

多項式p(x) = Σaᵢxⁱを，ホーナー法(Juliaの`evalpoly`)で評価すると，計算値は次の形に書ける(Higham，5.1節)．

```text
p̂(x) = (1 + θ₁)a₀ + (1 + θ₃)a₁x + (1 + θ₅)a₂x² + ⋯,   |θₖ| ≤ γₖ
```

高い次数の項ほど多くの丸めを受けるが，その項そのものが小さい．
誤差を|p̂ − p| ≤ γ₂ₙΣ|aᵢ||x|ⁱと一律に見積もると，ここでは約1.5 ULPも余分に見積もってしまう．
項ごとにγ₂ᵢ₊₁を掛ける見積もりを使うと，評価の誤差は約0.5 ULPになる．

## 6. 誤差予算

各段の誤差を，結果の絶対誤差に直して足し合わせる．これを誤差予算と呼ぶ．
r = −ln 2/2(結果が1より小さく，ULPがuになる，最も厳しい点)での内訳は次のとおりである．

| 段階 | 誤差の原因 | 大きさ(ULP) |
| --- | --- | --- |
| 還元 | rの丸め(u·rの絶対値)が，exp(r)倍されて伝わる | 0.245 |
| 打ち切り | テイラー多項式の剰余 | 0.053 |
| 評価 | Q(r)のホーナー法，係数の表現，r²と積とsの和の丸め | 0.492 |
| 復元 | 1 + sの丸め | 0.5 |
| 合計 | | 1.29 |

区間[−ln 2/2, ln 2/2]の20001点で予算を計算すると，この点の1.29 ULPが最大だった．
このコースでは，正規化数の結果の上界を1.3 ULPとする．

結果が非正規化数のときは，`ldexp`で2回目の丸めが入る(二重丸め)．
それまでの誤差(1 + sの丸めを含めて1.29 ULP)は，非正規化数の間隔を単位にすると1倍以下に縮み，そこに0.5 ULPが加わる．
上界は1.8 ULPである．

誤差予算は，「どの段を改良すれば上界が下がるか」も教える．
この実装では，評価(0.49)と還元(0.25)が大きい．
rを2つの浮動小数点数の和で持つ(double-word)などの工夫で，上界を1 ULP未満(忠実な丸め)まで下げられる．

## 7. 保証と実測

乱数の22万点で測った誤差の最大値は，正規化数で0.93 ULP，非正規化数で1.00 ULPだった．
実測の値は上界より小さいが，それは「試した点では小さかった」ことしか示さない．
仕様として主張できるのは，誤差予算で導いた上界の1.3 ULPである．
テストの許容誤差も，実測の値ではなく上界から決める．

上界が1 ULPを超えるので，単調性(x < x′ならexp(x) ≤ exp(x′))は保証されない．
連続する2つの浮動小数点数で，正しい値の差が1 ULPより小さい場合，誤差の向きによって順序が逆になりうるからである．
保証から導けない性質をテストに書くと，正しい実装を不合格にしうる．
テストする性質は，実装の保証から導けるものに限る．

## 8. 4種類の検査

初等関数は入力が実数全体にわたるので，検査の方法を組み合わせる．

| 検査 | 内容 | 見つけやすい誤り |
| --- | --- | --- |
| 標本検査 | 全範囲と0の近くから乱数で選んだ点で，`BigFloat`の参照解とULP誤差を比べる | 全体的な精度不足(多項式の次数が足りないなど) |
| 境界値検査 | オーバーフローとアンダーフローの境，正規化数と非正規化数の境，還元の切り替わり(±ln 2/2)，0の近く | 場合分けの誤り，閾値の誤り |
| 局所的な全数検査 | 誤差が出やすい点の前後の連続する浮動小数点数をすべて調べる | 乱数では当たりにくい，狭い範囲の誤り |
| 差分テスト | 信頼できる別の実装(`Base.exp`)と比べる | 参照解を使わずに多くの点を調べられる |

差分テストでは，比べる相手の誤差も許容誤差に含める．
`Base.exp`の誤差を1 ULP未満と仮定すると(実測の最大値は0.72 ULP)，2つの結果の差は(1.3 + 1) ULP以下である．
この仮定は誤差仕様書に書く．

`Float64`の全数検査(2⁶⁴個)は現実的でないが，`Float32`の指数関数なら2³²個の入力をすべて調べられる．
局所的な全数検査は，その考え方を誤差の出やすい区間に絞って使うものである．

## 9. テストのグループ

局所的な全数検査は時間がかかるので，テストのグループ`exhaustive`に分ける．
`Pkg.test(test_args = ["exhaustive"])`とすれば単独で実行でき，引数を省けばほかのグループと一緒に実行される．
