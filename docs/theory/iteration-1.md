# Iteration 1：桁落ち，後退誤差，条件数

このノートでは，二次方程式の根の公式を例に，計算結果の誤差を「問題の条件数」と「アルゴリズムの後退誤差」に分けて考える方法を学ぶ．
あわせて，fmaを使った積の無誤差変換と，高精度の参照解の作り方を扱う．

## 1. 桁落ち

近い値どうしの引き算では，上位の桁が打ち消し合い，結果の有効桁が減る．これを桁落ちと呼ぶ．

```julia
julia> 1.0 - 0.9999999
9.999999994736442e-8
```

正しい答えは1.0e-7で，結果の相対誤差は約5 × 10⁻¹⁰である．正しいのは先頭の9桁程度である．
引き算そのものは正しく丸められている．
誤差の原因は，`0.9999999`を倍精度で表したときにすでに入っていた相対10⁻¹⁶程度の誤差である．
入力の大きさは1程度，結果の大きさは10⁻⁷なので，入力の誤差は結果に対して相対的に約10⁷倍に拡大されて見える．

ここから2つのことが分かる．

- 引き算は，入力が厳密なら無害である．実際，yがx/2 ≤ y ≤ 2xを満たす浮動小数点数なら，x − yは丸めずに厳密に計算される(Sterbenzの補題)．
- 引き算が有害になるのは，入力にすでに誤差が含まれているときである．桁落ちは，前の計算の誤差を拡大して見せる．

総和の条件数κ = Σ|xᵢ|/|Σxᵢ|で言えば，x − yの条件数は(|x| + |y|)/|x − y|である．xとyが近いほど条件数が大きい．

## 2. 根の公式の桁落ち

二次方程式ax² + bx + c = 0の根は，次の公式で表される．

```text
x = (−b ± √d)/(2a),   d = b² − 4ac
```

この公式をそのまま計算すると，2つの場面で桁落ちが起きる．

### b² ≫ |4ac|のとき

√dは|b|にほぼ等しいので，−b + √d(b > 0のとき)で桁落ちが起きる．
√dは丸めた値なので，有害な桁落ちである．

```julia
julia> x1 = (-1e8 - sqrt(1e16 - 4)) / 2; x2 = (-1e8 + sqrt(1e16 - 4)) / 2; (x1, x2)
(-1.0e8, -7.450580596923828e-9)

julia> quadratic_roots(1.0, 1e8, 1.0)
(-1.0e8, -1.0e-8)
```

小さい根の正しい値は約−1.0e-8で，公式どおりに計算した値の相対誤差は25%である．

桁落ちは，計算を書き換えて避けられる．
bとsign(b)√dは同符号なので，その和は桁落ちしない．そこで，次のように計算する．

```text
q = −(b + sign(b)√d)/2,   r₁ = q/a,   r₂ = c/q
```

r₁は絶対値の大きい根で，r₂は解と係数の関係r₁r₂ = c/aから求めた絶対値の小さい根である．
どちらの計算にも，桁落ちする引き算がない．

### b² ≈ 4acのとき

2つの根が近いとき，判別式d = b² − 4acの計算そのもので桁落ちが起きる．
b²と4acは丸めた積なので，これも有害な桁落ちである．

Kahanが示した例では，正しい判別式は121/16 = 7.5625だが，そのまま計算すると0.0になる．

```julia
julia> a, b, c = 94906265.625, -189812534.0, 94906268.375;

julia> b^2 - 4a * c
0.0

julia> discriminant(a, b, c)
7.5625
```

## 3. fmaと積の無誤差変換

fma(融合積和演算)`fma(a, b, c)`は，a × b + cを1回だけ丸めて計算する．
a × bを丸めた値をpとすると，`fma(a, b, -p)`はa × b − pを1回の丸めで計算する．
a × b − pは浮動小数点数で厳密に表せる(オーバーフローとアンダーフローが起きない限り)ので，この計算には丸め誤差がない．
こうして，積を丸めた値と丸め誤差の組に誤差なく分解できる．これが`two_prod`である．

```julia
julia> two_prod(0.1, 0.1)
(0.010000000000000002, -8.326672684688674e-19)
```

Kahanの方法では，`two_prod`でb² = p + e_p，4ac = q + e_qと分解する．
打ち消しが大きいとき(3|p − q| < p + |q|)は，pとqが2倍以内に近いので，Sterbenzの補題からp − qは厳密に計算される．
これに丸め誤差の差e_p − e_qを加えれば，判別式の失われた桁が戻る．
Boldoは，この方法の誤差が2 ulp以内であることを形式的に証明した．
1 ulpは相対2u以下なので，判別式の相対誤差は4u以下(テストではγ₄)である．

## 4. 前進誤差と後退誤差

計算したい関数をf，入力をx，計算結果をŷとする．

- 前進誤差は，結果の誤差|ŷ − f(x)|(またはその相対誤差)である．
- 後退誤差は，ŷを厳密な答えとする入力x + Δxのうち，最も小さい|Δx|(またはその相対的な大きさ)である．

```text
       f
  x  ────→  f(x)
  │            ╲   前進誤差
  │ 後退誤差     ╲
  ↓      f       ↘
x + Δx ────→  ŷ = f(x + Δx)
```

後退誤差は「計算結果は，少しだけ違う問題の正しい答えである」と言い換える見方である．
後退誤差が常にu程度になるアルゴリズムを，後退安定(backward stable)と呼ぶ．
入力そのものに相対u程度の誤差(表現誤差)があるので，後退安定なアルゴリズムは，入力の誤差と同程度にしか結果を狂わせない．

Iteration 0の素朴な総和の解析Ŝ = Σxᵢ(1 + θ⁽ⁱ⁾)，|θ⁽ⁱ⁾| ≤ γₙ₋₁は，「Ŝは，各xᵢを相対γₙ₋₁以下だけ変えた入力の厳密な総和である」と読める．
つまり，素朴な総和の後退誤差はγₙ₋₁以下である．

## 5. 根の後退誤差と条件数

二次方程式p(x) = ax² + bx + cの近似根r̂を考える．係数をそれぞれ相対ε以下だけ変えてr̂を厳密な根にできる最小のεは，次の式で表される．

```text
η(r̂) = |p(r̂)| / (|a|r̂² + |b||r̂| + |c|)
```

これを根の(成分ごとの)後退誤差と呼ぶ．
分子の残差|p(r̂)|は，正しい根を知らなくても計算できる．
`root_backward_error`は，この式を有理数で厳密に計算する．

単根rについて，係数を相対ε以下だけ変えたときの根の相対的な変化は，一次の近似で次のように抑えられる．

```text
|Δr|/|r| ≲ κ_r · ε,   κ_r = (|a|r² + |b||r| + |c|) / |r · p′(r)|
```

κ_rを根の条件数と呼ぶ．p′(r) = 2ar + bは，2つの根が近いほど0に近づくので，近い根の条件数は大きい．
重根ではp′(r) = 0となり，条件数は無限大である．

## 6. 前進誤差 ≲ 条件数 × 後退誤差

4節と5節を組み合わせると，数値計算でいちばんよく使う見積もりが得られる．

```text
前進誤差  ≲  条件数  ×  後退誤差
```

Kahanの例で確かめる．根の条件数は約1.4 × 10⁸である．

```julia
julia> r = quadratic_roots(a, b, c)
(1.0, 1.0000000289759583)

julia> root_condition_number(a, b, c, r[1])
1.3804547927272728e8

julia> s = sqrt(b^2 - 4a * c); naive = minmax((-b - s) / (2a), (-b + s) / (2a))
(1.0000000144879793, 1.0000000144879793)

julia> root_backward_error(a, b, c, naive[1])
5.247538362694621e-17

julia> relative_error(r[1], exact), relative_error(naive[1], exact)
(0.0, 1.4487979260735528e-8)

julia> unit_roundoff(Float64) * root_condition_number(a, b, c, r[1])
1.5326126953399664e-8
```

`exact`は`BigFloat`で求めた参照解である(9節)．
公式どおりの計算(`naive`)の後退誤差は約5 × 10⁻¹⁷で，単位丸めより小さい．
後退誤差は小さいのに，前進誤差は約1.4 × 10⁻⁸で，κ_r·u ≈ 1.5 × 10⁻⁸とほぼ一致する．
前進誤差が大きいのはアルゴリズムが悪いからではなく，問題の条件が悪いからである．

この見積もりから，テストの方針が決まる．

- 条件の悪い問題で，前進誤差に固定の許容誤差(例えばγ₆)を使うと，後退安定な実装でも不合格になる．
- アルゴリズムの安定性を確かめたいなら，後退誤差を検査する．後退誤差は正しい答えを知らなくても計算できる．
- 前進誤差を検査するなら，許容誤差は「条件数 × 後退誤差の上界」から決める．

`StableNumerics`の`quadratic_roots`は，判別式を4u以内で計算するので，さらに強い保証を持つ．
Kahanの例でも，小さい方の根の相対誤差は0である．次の節で，この保証を導く．

## 7. quadratic_rootsの誤差界

1. 判別式d̂の相対誤差は4u以下である(3節)．
2. √d̂の相対誤差は，dの誤差の半分(√(1 + ε) ≈ 1 + ε/2)の2uと，平方根の丸めのuを合わせて3u以下である．
3. bとsign(b)√d̂は同符号なので，和の相対誤差は，項の相対誤差の大きい方(3u)と足し算の丸め(u)を合わせて4u以下である．2で割るのは厳密である．
4. q/aとc/qの割り算でuずつ加わり，各根の相対誤差は5u以下になる．

二次の項も含めた上界としてγ₆を使う．
判別式を素朴に計算すると，1の段階でdの相対誤差が判別式の条件数(b² + 4|ac|)/|b² − 4ac|に比例して大きくなる．その場合は，6節のように根の条件数に比例した前進誤差しか保証できない．

根の相対誤差εから，後退誤差の上界も導ける．r̂ = r(1 + ε)のとき，p(r) = 0から次の式が成り立つ．

```text
p(r̂) = r·ε·p′(r) + a·r²·ε²
```

|r·p′(r)| ≤ 2(|a|r² + |b||r|)なので，η(r̂) ≤ 2ε + ε²となり，ε ≤ γ₆ならη ≤ γ₁₂である．

## 8. 特殊値

IEEE 754の浮動小数点数には，有限の数のほかに±0，±Inf，NaNがある．

```julia
julia> -0.0 == 0.0, 1 / -0.0
(true, -Inf)

julia> Inf - Inf, NaN == NaN
(NaN, false)

julia> copysign(3.0, -0.0), copysign(3.0, 0.0)
(-3.0, 3.0)
```

- −0.0と0.0は`==`では等しいが，符号を持つ．`copysign`や割り算で違いが現れる．
- `Inf - Inf`や`0/0`は`NaN`になる．`NaN`はそれ自身とも等しくない．
- 実数の`sqrt`は負の引数で`DomainError`を投げる．

`quadratic_roots`の仕様では，係数が有限でないときとa = 0のときを`ArgumentError`とした．
特殊値の扱いは仕様の一部なので，テストリストに書いて検査する．
b = −0.0のときは`copysign(√d, b)`が負になるが，q = −(b + sign(b)√d)/2の和は桁落ちしないので，結果は正しい．

## 9. 高精度の参照解

根の公式には平方根があるので，有理数では厳密な根を表せない．
そこで，`BigFloat`(任意精度の浮動小数点数)で根を計算し，参照解とする．
参照解は，`Float64`の結果より十分正確でなければならない．精度は次のように見積もる．

- 判別式は有理数で厳密に求める．b²と4acの計算で誤差が入らない．
- 平方根と割り算の相対誤差は，pビットの精度で2⁻ᵖ程度である．
- 根の公式の引き算(−b + √d)で桁落ちが起きると，誤差は(|b| + √d)/|−b + √d|倍に拡大される．`QUADRATIC_CASES`の係数では，この倍率は最大で10²⁰である(a = c = 10⁻¹⁰，b = 1の場合)．

256ビットなら2⁻²⁵⁶ × 10²⁰ ≈ 10⁻⁵⁷で，u ≈ 10⁻¹⁶より十分小さい．

見積もりを実際に確かめる方法もある．
精度を2倍の512ビットにして計算し直し，参照解がほとんど変わらないことを確かめればよい．
模範解答のテストでは，256ビットと512ビットの参照解の相対差がu²以下であることを検査している．
参照解の誤差が許容誤差より十分小さくなければ，テストは実装の誤差を測れない．

## 10. 性質による検査：解と係数の関係

2つの根r₁，r₂について，r₁ + r₂ = −b/a，r₁r₂ = c/aが成り立つ(解と係数の関係)．
この関係は，参照解を使わずに検査できる性質である．
各根の相対誤差がγ₆以下なら，次の不等式が成り立つ．

```text
|r̂₁ + r̂₂ + b/a| ≤ (γ₆/(1 − γ₆))(|r̂₁| + |r̂₂|)
|r̂₁r̂₂ − c/a|    ≤ γ₁₂ |c/a|
```

左辺は`BigFloat`で計算する．
和の不等式の右辺が|b/a|ではなく|r̂₁| + |r̂₂|なのは，2つの根の符号が違うとr₁ + r₂で打ち消しが起きるからである．
この節の不等式も，誤差界から導いたものである．

性質による検査は，参照解による検査より弱い．
例えば，根の順序を入れ替えて返す間違いは，解と係数の関係では見つからない．
一方で，参照解が用意できない問題にも使える．Iteration 2では，性質による検査を主な手段として使う．
