# Iteration 0：浮動小数点数と総和の誤差

このノートでは，浮動小数点数の丸め誤差を式で扱う方法を学び，総和の誤差の上界を導く．
導いた上界は，そのままテストの許容誤差になる．

## 1. 浮動小数点数

Juliaの`Float64`は，IEEE 754の倍精度(binary64)である．
0でない有限の数は，符号・指数・仮数を使って次の形で表される．

```text
x = ±(1.f₁f₂…f₅₂)₂ × 2ᵉ    (−1022 ≤ e ≤ 1023)
```

仮数は53ビット(先頭の1を含む)なので，2ᵉ以上2ᵉ⁺¹未満の範囲には，間隔2ᵉ⁻⁵²で数が並ぶ．
この間隔をULP(unit in the last place)と呼ぶ．Juliaでは`eps(x)`がxのULPを返す．

```julia
julia> eps(1.0)
2.220446049250313e-16

julia> eps(1e16)
2.0

julia> 1e16 + 1.0 == 1e16
true

julia> nextfloat(1.0)
1.0000000000000002
```

1e16の近くでは数の間隔が2なので，1e16 + 1は表せない．
足した1.0は丸めで失われる(情報落ち)．

10進数の0.1も倍精度では表せない．
`Rational{BigInt}(0.1)`で，倍精度の0.1が実際に表している有理数が分かる．

```julia
julia> Rational{BigInt}(0.1)
3602879701896397//36028797018963968

julia> 0.1 + 0.2
0.30000000000000004
```

分母は2⁵⁵である．浮動小数点数は，どれも分母が2の冪の有理数である．
この事実は，後で厳密な参照解を作るときに使う．

## 2. 丸めと単位丸め

実数xを浮動小数点数に丸めた値をfl(x)と書く．
IEEE 754の既定の丸めは最近接偶数丸め(最も近い浮動小数点数に丸め，ちょうど中間なら仮数の最下位ビットが0の方に丸める)である．
オーバーフローとアンダーフローが起きなければ，次が成り立つ．

```text
fl(x) = x(1 + δ),   |δ| ≤ u
```

uを単位丸め(unit roundoff)と呼ぶ．`Float64`ではu = 2⁻⁵³ ≈ 1.11 × 10⁻¹⁶である．

名前の紛らわしさに注意する．
Juliaの`eps(Float64)`は1.0の次の数との差2⁻⁵²で，マシンイプシロンと呼ばれる．
単位丸めはその半分である．このコースでは，`unit_roundoff(T) = eps(T)/2`として区別する．

## 3. 丸め誤差の標準モデル

IEEE 754は，四則演算と平方根の結果が「正確な値を丸めたもの」になることを保証している．
したがって，浮動小数点数a，bと四則演算∘について次が成り立つ．

```text
fl(a ∘ b) = (a ∘ b)(1 + δ),   |δ| ≤ u
```

これを丸め誤差の標準モデルと呼ぶ．
誤差解析では，1回の演算ごとに(1 + δ)を掛け，δがいくつ積み重なるかを数える．

積み重なりを数えるための補題を1つ用意する．
|δₖ| ≤ uで，mu < 1なら，次が成り立つ．

```text
(1 + δ₁)(1 + δ₂)⋯(1 + δₘ) = 1 + θₘ,   |θₘ| ≤ γₘ = mu/(1 − mu)
```

上側は(1 + u)ᵐ − 1 ≤ e^(mu) − 1 ≤ 1/(1 − mu) − 1 = γₘから，下側は(1 − u)ᵐ ≥ 1 − mu ≥ 1 − γₘから分かる．
γₘは，m回の丸めの誤差をまとめて抑える定数である．mu ≪ 1ならγₘ ≈ muである．

## 4. 誤差の測り方

計算値x̂と正しい値xについて，誤差を次の2つで測る．

- 絶対誤差：|x̂ − x|
- 相対誤差：|x̂ − x|/|x|(x ≠ 0)

相対誤差が10⁻ᵏ程度なら，x̂はおよそk桁正しい．
浮動小数点数は相対的な精度で数を表すので，誤差は相対誤差で測るのが基本である．
ただし，正しい値が0や0の近くになる問題では相対誤差が意味を持たない．このときは絶対誤差を使うか，問題の大きさ(例えばΣ|xᵢ|)で割った誤差を使う．

## 5. 条件数

条件数は，入力の小さな相対的な変化が，出力では何倍の相対的な変化になるかを表す．
条件数はアルゴリズムではなく，問題そのものの性質である．

総和S = Σxᵢで，各xᵢをxᵢ(1 + εᵢ)，|εᵢ| ≤ εに変えたときの和の変化をΔSとする．

```text
|ΔS| = |Σxᵢεᵢ| ≤ ε Σ|xᵢ|,   したがって   |ΔS|/|S| ≤ ε · Σ|xᵢ|/|S|
```

そこで，総和の条件数を次のように定める．

```text
κ = Σ|xᵢ| / |Σxᵢ|
```

符号がそろっていればκ = 1である．
大きな値どうしが打ち消し合って和が小さくなると，κは大きくなる．
`[1e16, 1.0, -1e16]`ではκ ≈ 2 × 10¹⁶である．
入力を表すだけで相対u程度の誤差が入るので，κu ≥ 1の総和は，どんなアルゴリズムでも作業精度のままでは正しい桁を保証できない．

## 6. 素朴な総和の誤差解析

先頭から順に足す総和s₁ = x₁，sₖ = fl(sₖ₋₁ + xₖ)を考える．
標準モデルからsₖ = (sₖ₋₁ + xₖ)(1 + δₖ)，|δₖ| ≤ uである．これを展開すると次の式になる．

```text
Ŝ = sₙ = Σᵢ xᵢ ∏ₖ₌ₘₐₓ(ᵢ,₂)ⁿ (1 + δₖ)
```

x₁とx₂にはn − 1個，xₙには1個の(1 + δₖ)が掛かる．
補題から，Ŝ = Σxᵢ(1 + θ⁽ⁱ⁾)，|θ⁽ⁱ⁾| ≤ γₙ₋₁と書ける．したがって，次の上界が得られる．

```text
|Ŝ − S| ≤ γₙ₋₁ Σ|xᵢ|,   |Ŝ − S|/|S| ≤ γₙ₋₁ · κ
```

この上界は「誤差 ≤ (アルゴリズムの丸めの回数で決まる量) × (問題の条件数)」という形をしている．
Iteration 1では，この形を後退誤差と条件数の積として整理する．

上界は最悪の場合の値である．丸め誤差の符号がばらばらなら，実際の誤差はたいていずっと小さい．
それでも，上界は「これを超えたら実装が間違っている」と言い切れる値なので，テストの許容誤差に使える．

## 7. 無誤差変換TwoSum

浮動小数点数a，bの和の丸め誤差a + b − fl(a + b)は，それ自身が浮動小数点数で表せる(オーバーフローしない限り)．
Knuthは，この誤差を浮動小数点数の6回の演算で正確に求める方法を示した．

```julia
s = a + b
b_virtual = s - a
a_virtual = s - b_virtual
e = (a - a_virtual) + (b - b_virtual)
```

このとき，a + b = s + eが**厳密に**成り立つ．これを無誤差変換(error-free transformation)と呼ぶ．
aとbの大小を比べる分岐が要らないので，どんな順で値が来ても使える．

無誤差変換の主張は「誤差が0」なので，テストでは許容誤差を使わずに厳密に検査できる．
浮動小数点数はすべて有理数なので，`Rational{BigInt}`に直してa + bとs + eを比べればよい．

## 8. 補償付き総和Sum2

Ogita–Rump–OishiのSum2は，各段の和を`two_sum`で分解し，丸め誤差を別に集めて最後に足す．

```julia
s, c = 0.0, 0.0
for x in xs
    s, e = two_sum(s, x)
    c += e
end
return s + c
```

誤差の上界は次のとおりである(Ogita, Rump, Oishi 2005，命題4.5)．

```text
|Ŝ − S| ≤ u|S| + γₙ₋₁² Σ|xᵢ|,   |Ŝ − S|/|S| ≤ u + γₙ₋₁² · κ
```

第1項のuは最後に作業精度へ丸める分で，避けられない．
第2項はγₙ₋₁の2乗に比例する．κが1/(n²u)よりずっと小さければ，結果の精度は「2倍の精度で計算して丸めた」場合と同程度になる．

よく知られたKahanの補償付き総和は，補正をすぐ次の加数に足し込む．
このため，`[1e16, 1.0, -1e16]`では補正が失われ，0.0を返す．Sum2は補正を最後まで別に持つので1.0を返す．

## 9. 許容誤差の設計

テストで浮動小数点数を比べるとき，許容誤差の選び方には3つの失敗がある．

- `==`で比べる：丸め誤差のある計算では，正しい実装でも不合格になる．`0.1 + 0.2 == 0.3`は偽である．
- 許容誤差が大きすぎる：間違った実装も合格する．例えば最後に補償の項`c`を足し忘れた`compensated_sum`は，`rtol = 1e-8`で比べると，模範解答の5つのテストデータのうち3つ(条件数が小さいもの)で合格してしまう．誤差界u + γₙ₋₁²κで比べれば，5つとも不合格になる．
- 根拠なく決める：Juliaの`≈`は，既定で`rtol = √eps ≈ 1.5 × 10⁻⁸`を使う．この値は「倍精度の半分の桁が合えばよい」という便宜上の値で，個々の計算の誤差とは関係がない．0との比較では，`atol`を指定しない限り必ず偽になる．

```julia
julia> 0.1 + 0.2 ≈ 0.3
true

julia> 1e-20 ≈ 0.0
false

julia> isapprox(1e-20, 0.0; atol = 1e-15)
true
```

このコースでは，許容誤差を誤差界から導く．
誤差界が厳密な不等式なら，そのまま許容誤差に使える．
次の表は，模範解答のテストデータで測った相対誤差と，誤差界を比べたものである．

| データ | n | κ | 素朴な総和の誤差 | 上界γₙ₋₁κ | 補償付き総和の誤差 | 上界u + γₙ₋₁²κ |
| --- | --- | --- | --- | --- | --- | --- |
| 0.1を1000個 | 1000 | 1.00 | 1.41e-14 | 1.11e-13 | 5.55e-17 | 1.11e-16 |
| 調和級数1/k | 1000 | 1.00 | 2.12e-16 | 1.11e-13 | 2.54e-17 | 1.11e-16 |
| 交代級数(−1)ᵏ/k | 1000 | 10.8 | 2.81e-15 | 1.20e-12 | 7.86e-17 | 1.11e-16 |
| 大きな値の打ち消し | 3 | 2.00e16 | 1.00 | 4.44 | 0 | 1.10e-15 |
| 近い値の差 | 200 | 2.00e13 | 1.49e-2 | 4.42e-1 | 0 | 9.88e-15 |

素朴な総和の誤差は，条件数が大きいデータで大きくなる．それでも上界の中に収まっている．
補償付き総和は，どのデータでもほぼ単位丸めの精度を保っている．

上界の計算そのものにも丸め誤差がある．
γₙの計算は2回丸めるので，相対誤差γ₂程度ずれる．上界と実際の誤差の差に比べて十分小さいので，このコースでは無視する．

## 10. 参照解(テストオラクル)

テストには「正しい答え」が要る．これをテストオラクル(参照解)と呼ぶ．
数値計算では正しい答えを知らないことが多い．参照解をどう用意するかは，品質保証の中心の問題である．

総和では，浮動小数点数がすべて有理数であることを使う．
`Rational{BigInt}`で足せば，丸め誤差のない厳密な総和が得られる．
厳密な参照解は遅いが，テストでは問題にならない．

Iteration 1では，有理数で表せない値(平方根)の参照解として，高い精度の浮動小数点数`BigFloat`を使う．
Iteration 2以降では，参照解がなくても検査できる方法(性質，後退誤差，製造解)を学ぶ．
