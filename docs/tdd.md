# テスト駆動開発とテストリスト

このコースでは，すべての機能をテスト駆動開発(TDD)で作る．
このガイドでは，TDDの進め方，テストリストの書き方，単体テストと結合テストの分け方，テストの実行方法をまとめる．

## Red → Green → Refactor

TDDでは，次の3つの段階を短く繰り返す．

1. Red：まだ実装していない振る舞いのテストを1つ書き，実行して失敗することを確かめる．
2. Green：そのテストが通る最小限のコードを書く．
3. Refactor：テストが通ったまま，重複をなくし，名前や構造を整える．

Redの段階では，テストが**期待した理由で**失敗していることを確かめる．
Juliaの`@test`の失敗には2種類ある．

- Fail：式が`false`になった．期待値と実際の値の違いが表示される．
- Error：式の評価中に例外が起きた．未実装のスタブを呼んだときや，書き間違いがあるときに起きる．

スタブを呼んだときのErrorは，正しいRedである．
`UndefVarError`(名前の書き間違い)や`MethodError`(引数の型の違い)によるErrorは，テストかシグネチャの誤りなので，先に直す．

Greenの段階では，次の2つの進め方を使い分ける．

- 仮実装：テストの期待値をそのまま返す(例：`return 0.0`)．次のテストで一般化を迫られる．
- 明白な実装：実装がはっきりしているときは，最初から本物の実装を書く．

2つ目のテストで仮実装が通らなくなるようにテストを選ぶことを，三角測量と呼ぶ．

## 数値計算のTDD

数値計算のテストでは，期待値と許容誤差の両方が要る．次の順で考える．

1. 誤差仕様書に，その関数の誤差界を書く(設計の段階)．
2. テストでは，誤差界から許容誤差を計算する．期待値には，参照解(厳密な値や高精度の値)を使う．
3. 実装する．テストが通らなければ，許容誤差ではなく実装か誤差解析を見直す．

テストを通すために許容誤差を緩めることはしない．
許容誤差を変えるのは，誤差解析を直したときだけで，そのときは誤差仕様書も直す．

結果が厳密に決まる場合は`==`で比べる．
整数の和，2の冪による拡大縮小，無誤差変換の結果などがその例である．

## テストリスト

テストリストは，これから確かめる振る舞いを1行ずつ並べたものである．
各Iterationの最初に，要件と使用例を読んで`TESTLIST.md`に書く．

```markdown
## 単体テスト

### Interpolation

- [ ] t = 0では左端の値y₀をそのまま返す
- [ ] t = 1では右端の値y₁をそのまま返す
- [ ] t = 0.5，y₀ = 1.0，y₁ = 3.0では2.0を返す(丸めが起きないので厳密に一致)
- [ ] 相対誤差が誤差界γ₃·(|1 − t||y₀| + |t||y₁|)/|y|以下(参照解は有理数で計算)
- [ ] tが[0, 1]の外なら`ArgumentError`を投げる

## 結合テスト

- [ ] 格子点の値の表から補間した値が，誤差界の中で正しい値に一致する
```

テストリストは，次のように書く．

- 1行に1つの振る舞いを書く．「〜できる」ではなく，入力と期待する結果が分かるように書く．
- 易しいものから並べる．空の入力や1要素の入力のような単純な場合，次に典型的な場合，最後に誤差界や特殊値の場合を並べる．
- 期待値が厳密に決まるものと，許容誤差つきで比べるものを区別する．許容誤差つきのものには，誤差界を書く．
- 実装中に思いついたテストは，すぐには書かず，リストの末尾に加える．
- 既存のテストの期待値が変わるときは，「〜を…に変える」という項目を書く．
- 項目を実装したら`[x]`にする．

## 単体テストと結合テスト

| 種類 | 確かめること | 置き場所 | 読み込み方 |
| --- | --- | --- | --- |
| 単体テスト | 1つのモジュールの関数を，そのモジュールだけで確かめる | `test/unit/<モジュール名>_tests.jl` | `using StableNumerics.<モジュール名>` |
| 結合テスト | 公開されたAPIを組み合わせた計算の筋書きを確かめる | `test/integration/<筋書き>_tests.jl` | `using StableNumerics` |

- 単体テストのファイルはモジュールごとに1つで，モジュールがある限り使い続ける．機能が変わったら，同じファイルにテストを加えるか期待値を書き換える．
- 結合テストは，ライブラリの利用者が実際に行う手順(条件数を調べてから方法を選ぶ，など)をたどる．
- テストの参照解やテストデータは`test/helpers.jl`にまとめる．

## テストの実行

| 目的 | 操作 |
| --- | --- |
| パッケージのすべてのテスト | パッケージを有効にしたREPLのPkgモード(`]`)で`test` |
| 単体テストだけ | `using Pkg; Pkg.test(test_args = ["unit"])` |
| リポジトリのすべてのテスト | `mise run test` |
| すべての検査(リント，設計文書，テスト) | `mise run check` |

`Pkg.test`は新しいJuliaのプロセスでテストを実行する．
テストの結果は，最後に`Test Summary`の表で表示される．
