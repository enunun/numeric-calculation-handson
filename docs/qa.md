# 数値計算の品質保証

数値計算のプログラムのテストは，普通のプログラムのテストより難しい．
結果に丸め誤差や打ち切り誤差が含まれるので，「正しい答えと一致する」とは何かを決めなければならないからである．
このガイドでは，コース全体で使う品質保証の考え方をまとめる．
各手法の理論は，Iterationごとのノート(`docs/theory/`)で詳しく扱う．

## 何を保証するのか

数値計算の品質保証は，次の2つに分けて考える．

- 検証(verification)は，プログラムが意図した数学の問題を，主張した精度で解いているかを確かめる．
- 妥当性確認(validation)は，その数学の問題が現実の対象を十分よく表しているかを確かめる．

このコースが扱うのは検証である．
検証では「主張した精度」をはっきりさせることが出発点になる．
`StableNumerics`では，関数ごとの主張を誤差仕様書(`design/error-spec.md`)に書き，その主張をテストで確かめる．

```text
主張(誤差仕様書)  →  根拠(誤差解析)  →  検査(テスト)
```

この3つが対応していれば，テストが通ったことは「主張が成り立っている」ことの証拠になる．
対応が取れていないテスト(許容誤差を合格するまで緩めたテストなど)は，通っても何も保証しない．

## 誤差の分解：条件数と安定性

計算結果の誤差は，問題の性質とアルゴリズムの性質に分けて考える．

```text
前進誤差  ≲  条件数  ×  後退誤差
(結果の誤差)  (問題の感度)  (アルゴリズムの安定性)
```

- **条件数**は，入力の小さな変化が出力をどれだけ変えるかを表す．問題の性質で，アルゴリズムでは変えられない．
- **後退誤差**は，計算結果が「どれだけ近い入力に対する正確な答え」になっているかを表す．アルゴリズムの性質である．後退誤差が常に単位丸め程度のアルゴリズムを，後退安定という．

この分解から，テストの方針が決まる．

- 条件の悪い問題では，正しいアルゴリズムでも前進誤差が大きくなる．前進誤差に固定の許容誤差を使うと，正しい実装が不合格になる．許容誤差は「条件数 × 後退誤差の上界」から決める．
- 後退誤差は，多くの問題で正しい答えを知らなくても計算できる(例：連立1次方程式の残差)．アルゴリズムの安定性は，後退誤差で直接検査する．

## テストオラクル

テストには，計算結果が正しいかを判定する手段(テストオラクル)が要る．
数値計算では正しい答えを知らないことが多いので，問題に合わせて次のオラクルを使い分ける．

| オラクル | 考え方 | 使う場面 | 初出 |
| --- | --- | --- | --- |
| 厳密な参照解 | 有理数で厳密に計算する | 四則演算だけでできる計算 | Iteration 0 |
| 無誤差の主張 | 「誤差が0」という主張を厳密に検査する | 無誤差変換 | Iteration 0 |
| 高精度の参照解 | `BigFloat`で桁数を増やして計算する | 平方根や初等関数を含む計算 | Iteration 1 |
| 性質 | 答えが満たすべき関係(解と係数の関係，非負性など)を検査する | 答えは分からないが性質は分かる計算 | Iteration 1 |
| メタモルフィック関係 | 入力を変えたときの出力の関係(平行移動しても分散は同じ)を検査する | 答えは分からないが変換に対する振る舞いは分かる計算 | Iteration 2 |
| 後退誤差 | 残差から後退誤差を求め，誤差界と比べる | 方程式を解く計算 | Iteration 1，3 |
| 製造解 | 先に答えを決め，そこから問題を作る | 逆問題として問題を作れる計算 | Iteration 4，6 |
| 差分テスト | 信頼できる別の実装と比べる | 標準ライブラリなどに同じ機能がある計算 | Iteration 5 |
| 観測次数 | 刻み幅を変えたときの誤差の減り方を理論次数と比べる | 打ち切り誤差のある離散化(微分方程式の解法など) | Iteration 6 |
| 同じ算法の高精度実行 | 同じ算法を`BigFloat`で実行し，丸め誤差を取り除く | 打ち切り誤差と丸め誤差を分けたい計算 | Iteration 6 |
| 保存量・不変量 | 厳密な解が保つ量(エネルギー，角運動量)の変化を，丸め誤差の上界と比べる | 長い時間の計算，参照解を作れない計算 | Iteration 7 |

## 許容誤差の設計

浮動小数点数の比較には，`==`，相対誤差，絶対誤差，ULP誤差を使い分ける．

- `==`は，結果が厳密に決まるとき(整数の和，2の冪による拡大縮小，無誤差変換)に使う．許容誤差を使わずに済む場面を見逃さない．
- 相対誤差は，結果が0から離れているときの基本の尺度である．
- 結果が0や0の近くの値をとる場合は，絶対誤差を使う．誤差を何と比べるのか(例えば入力の大きさΣ|xᵢ|)を明示する．
- ULP誤差は，初等関数のように，結果をほぼ正しく丸めることが目標の計算で使う．

許容誤差の値は，誤差解析で導いた上界から決める．

1. 誤差仕様書に，誤差界を式で書く(例：相対誤差 ≤ γₙ₋₁·κ)．
2. テストでは，その式を`ErrorBounds`の`unit_roundoff`や`gamma`で計算して許容誤差にする．
3. 誤差界が厳密に示されていない場合(経験的な見積もりなど)は，その旨と，係数を決めた理由を誤差仕様書に書く．

根拠のない数値(`1e-10`など)を許容誤差に使わない．
許容誤差が大きすぎると間違った実装が合格し，小さすぎると正しい実装が不合格になる．
テストを通すために許容誤差を緩めたくなったら，それは誤差解析か実装を見直す合図である．

## テストデータの選び方

- 条件数を制御する．条件数が1のデータだけでは，不安定なアルゴリズムも合格してしまう．条件数が1から1/u程度まで広がるようにデータを選ぶ．
- 境界と特殊値を含める．0，±0，非正規化数，最大値の近く，`Inf`，`NaN`，空のベクトル，要素が1つのベクトルなどである．
- 乱数は再現可能にする．乱数でデータを作るときは，シードを固定し，失敗したときにシードが分かるようにする(Iteration 2)．

## テストの段階

| 段階 | 確かめること | 例 |
| --- | --- | --- |
| 単体テスト | 1つのモジュールの関数の主張(誤差界，性質，特殊値) | `compensated_sum`の相対誤差 ≤ u + γₙ₋₁²κ |
| 結合テスト | 公開APIを組み合わせた計算の筋書き | 条件数から誤差を見積もり，見積もりどおりの精度が出ることを確かめる |
| 設計文書の検査 | 誤差仕様書・依存図とコードの対応 | `mise run design` |

## 再現性

同じ入力に対して同じ結果が出ることも，品質の一部である．

- 浮動小数点数の演算は結合法則を満たさないので，足す順序が変わると結果が変わる．並列化やSIMD化で順序が変わることに注意する．
- fma(融合積和演算)を使うかどうかで結果が変わる．このコースでは，fmaを使う箇所を明示する(Iteration 1)．
- 乱数を使うテストは，シードを固定して実行するたびに同じデータを使う．

## このコースの流れ

| Iteration | 誤差の尺度 | オラクル | 品質保証の手法 |
| --- | --- | --- | --- |
| 0 | 相対誤差 | 厳密な参照解，無誤差の主張 | 誤差界から導く許容誤差 |
| 1 | 相対誤差，後退誤差 | 高精度の参照解，性質 | 特殊値と境界値，条件の悪い問題の扱い |
| 2 | 相対誤差 | 性質，メタモルフィック関係 | 性質ベーステスト，乱数シードの管理 |
| 3 | ノルムによる後退誤差 | 後退誤差 | 条件数を指定したテスト行列 |
| 4 | 前進誤差，直交性 | 製造解 | リファクタリングの安全網 |
| 5 | ULP誤差 | 高精度の参照解，差分テスト | 境界値・局所全数・標本検査の組み合わせ |
| 6 | 大域誤差，観測次数 | 製造解，観測次数，同じ算法の高精度実行 | 漸近展開から導く判定基準，漸近範囲の選択 |
| 7 | 保存量の変化 | 保存量・不変量，厳密な参照解(有理数) | 保証される性質の見極め，長時間の検査 |
